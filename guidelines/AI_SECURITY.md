# AI Security Guidelines

## Fail-closed 원칙

- `APP_ENV=production`에서는 `ALLOW_DEMO_BYPASS=false`만 허용합니다.
- 요청 본문, 모델명, UI 토글로 보안 정책을 해제할 수 없어야 합니다.
- 모델 공급자가 실패하거나 timeout이 나면 안전한 오류를 반환하며 원문 데이터는 노출하지 않습니다.

## 데이터 최소화

- LLM 컨텍스트에는 요청 처리에 필요한 최소 데이터만 넣습니다.
- 고객 데이터 검색은 사용자·테넌트 권한을 확인한 뒤 수행합니다.
- 감사 로그 원문 저장은 기본 비활성화이며, 활성화 전 보존기간·암호화·열람 권한·삭제 절차를 승인받습니다.

## 정책 변경

1. 공격/정상 입력을 함께 준비합니다.
2. 차단 근거와 오탐 가능성을 PR에 기록합니다.
3. 벤치마크로 방어율과 오탐률을 비교합니다.
4. 스테이징에서 shadow mode로 관찰한 뒤 차단 모드로 전환합니다.

정규식은 1차 방어일 뿐입니다. 다국어 우회·간접 프롬프트 인젝션·도구 호출은 정책 엔진, 권한 검증, 모델 평가로 중첩 방어합니다.
