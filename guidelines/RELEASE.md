# Release Guidelines

## Pull Request 체크리스트

- [ ] 입력 검증, 인증·인가, 오류 처리 영향을 검토했다.
- [ ] 실제 비밀·PII·`.env`·로컬 DB가 변경에 포함되지 않았다.
- [ ] `compileall`과 벤치마크가 통과했다.
- [ ] 가드레일 정책 변경 시 정상 입력 오탐을 확인했다.
- [ ] README, CHANGELOG, 관련 가이드 문서를 갱신했다.

## 배포 절차

1. CI의 테스트·Docker 이미지 빌드가 통과했는지 확인합니다.
2. 스테이징에서 API health check, 권한 검증, 차단/마스킹 시나리오를 확인합니다.
3. 지표 기준선(오류율, P95, 차단율, 오탐률)을 기록합니다.
4. 프로덕션에 점진 배포하고 30분 이상 지표를 관찰합니다.
5. 이상 시 직전 이미지로 롤백하고 감사 이벤트를 보존합니다.

## 릴리스 금지 조건

- `ADMIN_API_KEY`가 없거나, CORS에 `*`가 포함된 경우
- 데모 우회가 켜진 경우
- 모델·DB 연결 오류율이 기준을 초과한 경우
- 공격 방어율 또는 정상 요청 통과율이 팀 기준을 충족하지 못한 경우
